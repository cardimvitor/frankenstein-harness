# Study notes: Codex CLI and Hermes Agent

Read on 2026-09-30 from shallow clones of `openai/codex` (Apache-2.0) and `NousResearch/hermes-agent` (MIT). Read-only research: **no code was copied**; this project stays a clean-room MIT implementation. Only the parts named below were read; neither codebase was audited in full (Hermes' `agent/` alone is over 100k lines).

## Codex CLI (Rust)

| Area | What it does | Keep / avoid for this project |
|---|---|---|
| Linux sandbox | Bubblewrap is the default filesystem sandbox (system `bwrap` if present, otherwise a bundled copy); Landlock is the legacy path. It warns at startup when bubblewrap cannot create user namespaces and refuses sandboxed commands under WSL1. | **Different choice, deliberately kept:** Landlock + seccomp applied in-process by re-executing our own binary, with bubblewrap as `FH_SANDBOX=bwrap`. Landlock needs no external binary and works in containers, but it cannot hide or mask paths (no mount namespace), so credential directories are denied by *not granting* them. **Copy the startup diagnostics idea:** `fh doctor` already reports the Landlock ABI; it should also warn when neither backend works. |
| Windows sandbox | A separate crate that provisions dedicated sandbox user accounts (an offline and an online identity) once with elevation, protects their credentials with DPAPI, uses capability SIDs and ACLs per workspace (with explicit deny-read entries), a firewall-based network policy, a runner process reached over IPC, and ConPTY. | This is the shape of a *real* Windows sandbox: separate low-privilege identities plus ACLs, not a flag on the child process. It needs an installer step with administrator rights. **Avoid** trying to fake it with a job object alone; job objects give kill-on-close and resource limits, not file confinement. For us: job objects now (see ROADMAP), and either the account+ACL design later or a documented VM/container requirement. |
| Exec policy | `prefix_rule(pattern=[...], decision=allow\|prompt\|forbidden, justification, match, not_match)`; alternatives inside a pattern; examples validated when the file loads; host-executable path constraints. | **Adopted** (own format and code): `.fh/rules.json` / user `rules.json`, prefix patterns with alternatives, `match`/`not_match` examples checked at load, strictest decision wins, chained commands split and each part checked, redirections and substitutions never auto-allowed, project `allow` rules only in a trusted workspace. Not adopted: Starlark syntax, host-executable resolution. |
| Editing | Models are driven through an `apply_patch` tool with a small grammar (`*** Begin Patch`, Add/Delete/Update File with `@@` context hunks); the parser is lenient because some models emit slightly wrong patches. | Our search/replace `edit` is better matched to Qwen. **Adopted the useful part:** several changes in one file go in one call (`edits`), applied in order, all or nothing, so fewer model turns. |
| Layout | Many small crates (core, exec, hooks, mcp, memories, sandbox, TUI, app-server, cloud tasks...). | Avoid copying the split: a single crate with modules is easier to build and ship here. |

## Hermes Agent (Python)

| Area | What it does | Keep / avoid for this project |
|---|---|---|
| Context-file screening | AGENTS.md, `.cursorrules` and similar files that arrive with a checkout are scanned for injection and C2-style wording; a hit **blocks** the file (a user's own files only warn). Patterns anchor on attack behaviour, not on imperative English, because "you must" is normal in project guidance. | **Adopted** (own patterns): `src/skills/threat.rs`. Untrusted checkout: a matching AGENTS.md / SKILL.md is withheld with a warning; after `fh trust` it loads with a warning. Tests include benign guidance that must not be flagged. |
| Lint after edit | File edits run a quick syntax check per language and return the result to the model, skipping checks that would only produce noise. | **Adopted**: Python (`ast`), JS (`node --check`), shell (`bash -n`), JSON in-process; reported inside the edit result so the model fixes it in the same turn instead of a whole verification round later. |
| Skill curator | Background maintenance driven by inactivity: activity timestamps move skills to stale (14 days) and archived (30 days), pinned skills are exempt, nothing is ever deleted, an optional LLM consolidation pass, all fenced from the main session. | Our store already versions, quarantines and rolls back. **Still to adopt:** deterministic stale/archive by inactivity and a pin flag. Avoid autonomous LLM consolidation until the eval shows it helps. |
| Background review | After a turn, a forked agent that shares the parent's cached system prompt (so it hits the same prefix cache) reviews whether to save a skill or memory, under a tool whitelist. | Our miner and IMPROVE run post-delivery with data-only validation and rate limits. **Idea worth testing on vLLM:** run those calls with the stable prefix so they reuse the prefix cache. |
| Recovery | An empty-response guard, error classification and turn recovery. | **Adopted the small part:** an empty reply with no tool use is nudged twice before it is accepted. |
| Learning loop, memory | Agent-curated memory, cross-session search (FTS5 with LLM summaries), a user model, subagent delegation, cron, many terminal backends (local, Docker, SSH, ...), native Windows support. | Cross-session search over past tasks (our session logs) is the one with the best cost/benefit and is on the ROADMAP. Avoid the rest: it is a general assistant, this is a code-only harness. |

## Not studied
The Codex TUI, hooks and memories crates and Hermes' context compressor (5.6k lines) were listed but not read. Findings above are from the specific files named in the notes, not from a full review.
